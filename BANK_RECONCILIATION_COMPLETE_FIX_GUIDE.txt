ROOT CAUSE IDENTIFIED:
========================
✓ All banks point to SAME GLAccountID (Chart of Accounts head)
✓ acc_entries only stores account_id (not bank_id)
✓ No way to distinguish which bank each entry belongs to
✓ Filtering by account_id = @BankAccountId returns ALL transactions

Example:
	pos_banks:
		Bank A → GLAccountID = 18
		Bank B → GLAccountID = 18
		Bank C → GLAccountID = 18

	acc_entries:
		Transaction 1 → account_id = 18 (which bank? unknown!)
		Transaction 2 → account_id = 18 (which bank? unknown!)
		Transaction 3 → account_id = 18 (which bank? unknown!)

	Result: Cannot filter by bank!

================================================================================

SOLUTION: Add bank_id Column to acc_entries
=============================================

This tracks which bank account each entry belongs to:

	acc_entries:
		Transaction 1 → account_id = 18, bank_id = 1 (Bank A)
		Transaction 2 → account_id = 18, bank_id = 2 (Bank B)
		Transaction 3 → account_id = 18, bank_id = 3 (Bank C)

	Result: Now we can filter by bank_id! ✓

QUESTIONS & ANSWERS:
════════════════════

Q: Why not just use separate GL accounts for each bank?
A: That would require changing Chart of Accounts structure and massive 
   data migration. Adding bank_id is much simpler.

Q: Will this affect other forms/reports?
A: No. bank_id is nullable and only used in reconciliation. Other 
   forms/reports are unaffected.

Q: What if historical data can't be tied to a bank?
A: Those entries remain NULL for bank_id and won't show in reconciliation.
   Going forward, new entries will have bank_id populated correctly.

Q: Can we auto-populate bank_id based on something else?
A: Yes, if there's another field that links to a bank (party, cost center, 
   memo, etc.), we can use that. Discuss with business users.

## How to Add a New Feature

### Example: Add "Reversal" Button

**1. Wire the button in `frm_stock_check_adjustment.shortcuts.cs`:**

```csharp
private void WireToolbarButtons()
{
	// ... existing buttons ...
	if (btnReverseSession != null)
		btnReverseSession.Click += (s, e) => ReverseSessionWithConfirmation();
}
```

**2. Implement the handler in `frm_stock_check_adjustment.shortcuts.cs`:**

```csharp
private void ReverseSessionWithConfirmation()
{
	var reason = PromptString("Reversal Reason", "Why are you reversing this session?");
	if (string.IsNullOrWhiteSpace(reason))
		return;

	try
	{
		var bll = new StockAdjustmentBLL();
		bll.ReverseAdjustment(_currentAdjId, reason, UsersModal.logged_in_user_id);

		MessageBox.Show("Session reversed successfully.", "Success", MessageBoxButtons.OK, MessageBoxIcon.Information);
		SetSessionStatus("Reversed");
		MarkClean("Session reversed at " + DateTime.Now.ToString("HH:mm"));
	}
	catch (Exception ex)
	{
		MessageBox.Show("Reversal failed: " + ex.Message, "Error", MessageBoxButtons.OK, MessageBoxIcon.Error);
	}
}
```

## How to Update the Database Schema

**Follow this order (always):**

1. **Backup production database**
2. **Run `StockAdjustmentSchema.sql`** (will add/modify tables, indexes, triggers, views)
3. **Run `StockAdjustmentProcedures.sql`** (will add/replace stored procedures)
4. **Test in UAT** (run adjustment workflow end-to-end)
5. **Deploy to production**

> **Never** skip steps or mix procedures from different versions. The scripts are idempotent within a single version but may conflict across versions.

## Key Methods & When to Use Them

### UI Layer (`frm_stock_check_adjustment.cs` and partials)

| Method | Purpose | When to Call |
|--------|---------|--------------|
| `LoadNewSession()` | Generate new adj# | User clicks "New Session" |
| `SetSessionStatus(status)` | Update status badge | After status change (Draft→In Progress→Posted→Reversed) |
| `UpdateVerificationProgress(verified, total)` | Update progress bar | After batch verify or row update |
| `RefreshAdjustmentGrid()` | Refresh grid display | After rows added/removed/modified |
| `RefreshRecentGrid()` | Refresh recent items list | After rows added to session |
| `UpdateBottomSummary(...)` | Update status bar totals | After any change (typically via UI event) |
| `MarkDirty()` | Set unsaved-changes flag | In any edit handler |
| `MarkClean(msg)` | Clear unsaved flag, optionally update status | After successful Save/Post |
| `ShowProductDrawerForRow(rowIndex)` | Show product details panel | User presses F4 or clicks cell |
| `ToggleScanMode(isOn)` | Toggle barcode-scan overlay | User presses F6 |
| `UndoLastEdit()` | Pop undo stack | User presses Ctrl+Z or clicks Undo button |
| `RedoLastEdit()` | Pop redo stack | User presses Ctrl+Y |

### Business Logic Layer (`POS.BLL\POS\StockAdjustmentBLL.cs`)

| Method | Purpose | Parameters |
|--------|---------|------------|
| `CreateAdjSession(model)` | Create Draft session | `AdjSessionModel` with AdjType, WarehouseId, CreatedBy |
| `SaveAdjLines(adjId, lines)` | Upsert lines in Draft session | adjId, list of `AdjSessionLineModel` |
| `PostAdjustmentBatch(adjId, userId)` | Post session (applies to stock, marks Posted) | adjId, userId for audit |
| `ReverseAdjustment(adjId, reason, userId)` | Reverse a Posted session | adjId, reversal reason, userId |
| `UpdateLineVerified(lineId, isVerified)` | Mark line as verified | lineId, boolean |
| `GetAdjSessionById(adjId)` | Fetch session header | adjId |
| `GetAdjLines(adjId)` | Fetch all lines in session | adjId |
| `GetSessionSummary(adjId)` | Fetch aggregates (qty changes, price changes) | adjId |
| `GetAdjustmentHistory(productId, fromDate, toDate)` | Fetch audit trail for product | productId, date range |

### Data Access Layer (`POS.DLL\POS\StockAdjustmentDLL.cs`)

These call SQL stored procedures directly. Generally, **do not call these from the UI**; use BLL methods instead.

| Method | Stored Procedure | Returns |
|--------|------------------|---------|
| `CreateAdjSession(model)` | `sp_StockAdjustment_CreateSession` | `AdjSessionCreateResult` (adj_id, adj_no) |
| `SaveAdjLines(adjId, lines)` | `sp_StockAdjustment_UpsertLine` (per line, via batch/bulk) | void |
| `PostAdjustmentBatch(adjId, userId)` | `sp_PostStockAdjustment` | `AdjPostResult` |
| `ReverseAdjustment(adjId, reason, userId)` | `sp_StockAdjustment_Reverse` | void |
| `GetSessionSummary(adjId)` | `sp_GetSessionSummary` (custom query) | `AdjSessionSummaryModel` |

## Troubleshooting

### Build Errors

| Error | Cause | Fix |
|-------|-------|-----|
| `CS0111: Type already defines a member` | Duplicate method in partials | Check all `.cs` files for the same method name; keep only one definition |
| `CS0103: Name does not exist` | Missing field or method | Verify it's defined in a partial, not removed; check for typos |
| `CS1501: No overload for method` | Wrong parameter count/type | Check BLL method signature vs. call site |

### Runtime Errors

| Error | Cause | Fix |
|-------|-------|-----|
| "Adjustment session not found" | `adjId` passed to DLL doesn't exist in DB | Ensure session is created before saving lines; use return value from `CreateAdjSession` |
| Null reference on grid scroll | `_sessionRows` not initialized | Ensure `_sessionRows = new List<AdjustmentGridRow>()` is called |
| "Product not in index" search failure | Product index empty or stale | Check `BeginBuildProductIndexAsync()` completion; wait for "Product index ready" message |
| Grid doesn't refresh | `_gridAdjustment.RowCount` not updated | Call `SetGridRowCount(_sessionRows.Count)` after modifying `_sessionRows` |

### Dirty Tracking Not Working

**Symptom**: No auto-save at 5-min mark; form-close doesn't warn about unsaved changes

**Check**:
1. Is `MarkDirty()` being called in your edit handler? → Add it if missing
2. Is `_autoSaveTimer.Start()` called in `InitializeShortcutsAndWorkflow()`? → Check `frm_stock_check_adjustment.shortcuts.cs` line ~43
3. Are `AutoSaveTimer_Tick` and `FrmStockCheckAdjustment_FormClosing` wired? → Check event subscriptions in `InitializeShortcutsAndWorkflow()`

## Security Notes

- ✅ **Parameterized queries**: All DLL methods use `SqlParameter` (no SQL injection risk)
- ✅ **User audit trail**: `UsersModal.logged_in_user_id` captured in `sp_PostStockAdjustment` and reversal
- ✅ **Permission check**: (If applicable) Add `FormSecurityExtensions.ApplyPermissions` to read `Tag` values and enforce role-based access
- ⚠️ **Data validation**: BLL methods validate IDs and status values before calling DLL; do not trust UI input

## Performance Notes

- **Virtual grid**: Can handle 50,000+ rows without lag due to `RowCount` assignment (not per-row `Rows.Add()`)
- **Product index**: Async-loaded on background thread; prevents UI freeze during search initialization
- **Search**: Takes ~50–200 ms for full index scan; scoring algorithm prioritizes exact/prefix matches
- **Double-buffering**: Reflection-based property setting eliminates flicker on scroll/paint
- **Undo stack**: Limited to 20 records to avoid memory bloat; older records discarded via trimming

## Testing Tips

**Verify Session Workflow**:
1. Run form, check "Draft" badge appears
2. Click "New Session", verify adj# generated in `txtAdjustmentNo`
3. Search for product, click to add
4. Edit cell (e.g., New Qty), verify cell highlights with light-yellow background
5. Press Ctrl+Z, verify edit reverts
6. Press F9 (Save), check status bar updates with "Draft saved at HH:MM"
7. Press F10 (Post), confirm dialog appears, click Yes, verify status → "Posted"

**Verify Dirty Tracking**:
1. Edit a cell
2. Do not save; wait 5 minutes
3. Check status bar shows "Auto-saved at HH:MM"
4. Close form
5. Prompt "unsaved changes?" should **NOT** appear (because auto-save cleared `_isDirty`)

**Verify Undo**:
1. Edit multiple cells
2. Ctrl+Z repeatedly; each edit should revert
3. After emptying undo stack, Ctrl+Z does nothing (no error)
